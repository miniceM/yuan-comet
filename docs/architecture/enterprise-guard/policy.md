# Enterprise Guard 策略与规则目录

> 版本：v1.0 · 最后更新：2026-08-28 · 负责人：Comet maintainers · 评审：Proposed（Issue #2）

本文是 Enterprise Guard 的策略事实来源。规则引擎必须分别产生符合 [规则结果契约](contracts/enterprise-rule-result.v1.schema.json) 的结果；不允许把多个规则折叠成不可审计的单一正则表达式或自由文本提示。

## 决策词汇

| 字段      | 含义                                                 |
| --------- | ---------------------------------------------------- |
| `hard`    | 命中时拒绝执行；所需输入不可可靠取得时同样拒绝。     |
| `soft`    | 命中时告警并留给人工或 CI 决定；不会被转换为硬阻断。 |
| `allow`   | 该规则在完整、可用输入中没有发现违规。               |
| `deny`    | 阻断当前工具调用或 CI 步骤。                         |
| `warn`    | 记录可操作的告警，不假装已阻断。                     |
| `abstain` | 当前规则不适用；它不是全局放行。                     |

最终执行器的聚合规则固定为：任一有效 `hard/deny` 阻断；不存在 `hard/deny` 且至少一个 `soft/warn` 时告警；其余结果不改变平台原有权限流程。只有平台矩阵允许阻断时，`deny` 才能映射为平台阻断输出；否则它必须作为 CI 失败或明确诊断呈现。

## 未知输入与解析失败矩阵

| 规则等级 | 输入状态                                            | 结果      | 原因                                                      |
| -------- | --------------------------------------------------- | --------- | --------------------------------------------------------- |
| HARD     | 完整且命中                                          | `deny`    | 已取得违规证据。                                          |
| HARD     | 完整且未命中                                        | `allow`   | 只对该规则放行。                                          |
| HARD     | `partial`、`failed`、`unavailable` 或相关片段被截断 | `deny`    | `EG-HARD-INPUT-001`：无法安全判断的关键输入不能成为旁路。 |
| SOFT     | 完整且命中                                          | `warn`    | 暴露风险并要求 CI 或人工确认。                            |
| SOFT     | `partial`、`failed`、`unavailable` 或相关片段被截断 | `warn`    | 记录不确定性，不能伪装为安全。                            |
| 任意     | 平台/事件不适用                                     | `abstain` | 交给其他规则或 CI；禁止据此得出“全部允许”。               |

解析器必须逐字段设置 `capturedBytes`、`originalBytes` 和 `truncated`，并把原始解析错误写入 `parse.errors`。日志仅保存规则 ID、路径类别、摘要和已脱敏证据，不能复制密钥、完整写入片段或命令凭据。

## HARD 规则目录

| 规则 ID              | 判定边界                                                                           | `deny` 条件                                                                                                    | 不命中的边界                                                                                              |
| -------------------- | ---------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- |
| `EG-HARD-ENV-001`    | 创建、编辑、重命名或删除真正的环境文件。                                           | 路径段是 `.env` 或以 `.env.` 开头。                                                                            | `.env.example`、`.env.sample` 和带有这些后缀的模板不命中；它们仍受密钥规则检查。                          |
| `EG-HARD-SECRET-001` | 写入片段或命令参数中出现高置信度明文凭据。                                         | 赋值上下文、已知凭据前缀或私钥块与足够长度的秘密材料同时出现。                                                 | 环境变量引用、明确脱敏值、示例占位符和测试专用虚构值不命中；低置信度高熵字符串交给 `EG-SOFT-SECRET-002`。 |
| `EG-HARD-RM-001`     | Shell 删除命令会删除系统根、用户根、仓库根、当前工作目录、父目录或未限定通配范围。 | `rm`/等价删除命令带递归强制选项，且目标解析到上述受保护范围，或目标不能可靠解析。                              | 删除一个已规范化且位于工作区内的具体缓存目录不命中；仍应遵守项目规则。                                    |
| `EG-HARD-GIT-001`    | 对受保护分支执行强制推送。                                                         | 已解析目标分支属于受保护集合，且命令使用 `--force`、`-f` 或 `--force-with-lease`；无法解析目标分支时同样拒绝。 | 已知为非受保护分支的强制推送不命中本规则，但会触发 `EG-SOFT-GIT-002`。                                    |

`EG-HARD-INPUT-001` 是元规则：对任一 HARD 规则，缺失、失败或截断了该规则所需的命令、路径或写入片段时拒绝。它不是对不相关事件的默认阻断；不相关事件应以 `abstain` 结束。

## SOFT 规则目录

| 规则 ID              | 判定边界                                                           | 结果                                         |
| -------------------- | ------------------------------------------------------------------ | -------------------------------------------- |
| `EG-SOFT-SECRET-002` | 高熵字符串或可疑凭据名称缺少足够上下文，无法达到 HARD 的高置信度。 | `warn`，要求 CI Secret Scanner 或人工复核。  |
| `EG-SOFT-DELETE-002` | 删除范围广但已证明在非受保护工作区内。                             | `warn`，提供规范化目标与确认建议。           |
| `EG-SOFT-GIT-002`    | 已证明目标为非受保护分支的强制推送。                               | `warn`，保留远端分支和命令摘要供审计。       |
| `EG-SOFT-POLICY-003` | 平台 Hook 本身已被禁用、超时或报告非阻断故障。                     | `warn`，要求 CI 兜底；不得输出“已强制执行”。 |

## 例外机制

例外必须存为独立、受保护的 [例外记录](contracts/enterprise-exception.v1.schema.json)，并同时满足以下条件：

1. `ruleId` 精确匹配当前规则，`scope.kind` 与 `scope.value` 精确描述路径、分支、仓库或命令；`*` 及未限定通配不合法。
2. `reason` 可审计，`owner` 可联系，`expiresAt` 仍在未来；过期或撤销的记录不生效。
3. `approval` 指向受保护引用上的审批事实，且 `ci` 记录同一受保护引用上已通过的检查。
4. 规则引擎在应用例外前验证 Schema、状态、过期时间、审批引用与 CI 引用；任何验证失败都按“无例外”处理。

不接受命令、提交信息、提示词或写入内容中的内联旁路。诸如“已获批准”“ignore guard”“skip policy”及其变体都不能改变规则结果，也不能替代例外记录。

例外只把指定规则对指定范围的 `deny` 变为 `warn`，并在结果中写入 `exceptionId`；它不会自动放行其他 HARD 规则，也不会关闭 CI 检查。
